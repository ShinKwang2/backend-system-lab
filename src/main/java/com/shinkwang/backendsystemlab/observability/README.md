# Observability / 지표·로그·추적

직접 배운 관측을 지속적으로 수집하고, 증상에서 가설과 추가 확인으로 이어지는 관측 체계를 만든다.

전체 위치와 순서: [CURRICULUM.md](../../../../../../../docs/CURRICULUM.md) · [현재 진도](../../../../../../../docs/PROGRESS.md)

## 시작 조건

Actuator의 작은 사용은 필요한 Lab에서 먼저 한다. 스택 통합은 CLI·JVM·DB 관측과 여러 장애 실험 후 진행한다.

## 첫 설명

지표는 변화의 크기와 추세를, 로그는 개별 사건을, trace는 요청이 여러 구간을 지나는 흐름을 볼 수 있게 한다. 도구가 늘어도 근거로 가설을 좁히는 과정은 같다.

## 도구를 처음 사용할 때

아래 표는 명령어 사전이다. 첫 수업에서는 필요한 명령 하나와 출력 항목 2~3개만 소개한다. `<PID>`, `<PORT>`, `<PATH>`, `<실험경로>`는 실제 값으로 바꾸는 자리 표시자이며 그대로 실행하지 않는다. 아직 없는 API나 설정은 해당 단계에서 함께 만든다.

| 명령·도구 | 목적과 입력 | 처음 읽을 항목·종료 |
| --- | --- | --- |
| Actuator / Micrometer | 프로젝트에 있는 Actuator부터 사용하고 실제 endpoint 노출 범위와 지표 목록을 확인한다. | HTTP 지연·오류·JVM·스레드·풀. 지표 이름·단위·범위를 먼저 확인하며 실험 환경만 노출. |
| Prometheus / Grafana | 필요해진 지표를 수집·시각화한다. | counter·gauge·histogram, 조회 구간·rate·분위수·label 범위. 처음에는 대시보드 하나. |
| 구조화 로그 / Trace | 요청 ID와 의존성 구간의 시간을 연결한다. | 관측 시각·오류·span 범위·샘플링. 민감 데이터와 label cardinality를 확인. |

## 세부 커리큘럼

### OBSERVABILITY-01 — 지표가 답하는 질문

- 배울 것: 사용자 지연·실패·처리량과 자원 포화, 지표 종류·단위를 배운다.
- 안내 실습: 이미 실험한 장애 하나에서 Actuator 지표를 CLI 관측과 대조한다.
- 예상·가설 질문: CPU 지표의 대상이 JVM인지 호스트인지 어떻게 알까? 평균 지연이 놓치는 것은 무엇일까?
- 완료 기준: 지표마다 질문·대상·단위·시간 구간을 적는다.

### OBSERVABILITY-02 — 작은 수집·대시보드

- 배울 것: scrape, 시간 구간, 집계·분위수의 의미를 배운다.
- 안내 실습: Prometheus·Grafana를 필요한 시점에 추가하고 장애 하나의 정상·주입·회복을 같은 대시보드에서 본다.
- 예상·가설 질문: 서로 다른 수집 간격의 지표를 같은 순간 값처럼 비교해도 될까?
- 완료 기준: 대시보드와 실제 덤프·DB 증거를 연결하고 빨간 그래프만으로 원인을 단정하지 않는다.

### OBSERVABILITY-03 — 가설 트리와 통합 진단

- 배울 것: CPU·GC·락·Pool·SQL·Network·외부 API의 구분 질문을 배운다.
- 안내 실습: 익숙한 장애를 하나씩 비공개 조건으로 재현한다. 학습자가 관찰 계획을 정하고 필요한 지표·로그·trace·직접 도구를 선택한다.
- 예상·가설 질문: 현재 가설을 반증할 수 있는 증거는 무엇일까? 비슷한 증상의 다른 원인은?
- 완료 기준: 학습자가 증상 → 관찰 → 가설 → 검증 → 원인 → 해결·재검증 보고서를 작성하고 판단의 한계를 설명한다.

## 해석할 때 지킬 경계

관측은 마지막에 처음 배우는 주제가 아니다. CLI·JVM·DB와 필요한 Actuator 지표는 처음부터 학습하고, 큰 수집 스택은 뒤에 통합한다. 지표만으로 원인을 확정하지 않고 직접 관찰과 연결한다.

## 수업과 기록

각 단계에서 기초 설명 → 정상 관찰 → 예상 → 조건 하나 변경 → 실제 관찰 → 가설과 검증 → 정리 순서로 진행한다. 도구 입문은 장애 주입이나 해결이 없어도 된다. 첫 실험은 안내형, 반복 실험은 힌트형, 마지막 적용은 독립형으로 도움을 줄인다.

실제 출력과 자기 설명은 [실험 기록 양식](../../../../../../../docs/EXPERIMENT-TEMPLATE.md)으로 남긴다. 현재 이 문서는 계획이며 어떤 단계도 완료로 표시하지 않는다. 다음 단계는 고정된 날짜가 아니라 실제 관찰과 이해를 확인한 뒤 선택한다.
