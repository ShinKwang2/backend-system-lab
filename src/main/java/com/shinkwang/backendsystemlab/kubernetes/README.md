# Kubernetes / 기존 장애를 Pod에서 재현

기존 Linux·JVM 장애를 Kubernetes 자원과 수명 주기에 연결한다.

전체 위치와 순서: [CURRICULUM.md](../../../../../../../docs/CURRICULUM.md) · [현재 진도](../../../../../../../docs/PROGRESS.md)

## 시작 조건

Container·DB·Network·Messaging·Resilience. 격리된 학습 클러스터가 필요하며 처음부터 설치하지 않는다.

## 첫 설명

Pod 안에서도 앱은 CPU·메모리·연결을 사용하는 프로세스다. 이제 자원 제한, 트래픽 전달, 상태 검사, 재시작이 그 앱에 어떤 영향을 주는지 본다.

## 도구를 처음 사용할 때

아래 표는 명령어 사전이다. 첫 수업에서는 필요한 명령 하나와 출력 항목 2~3개만 소개한다. `<PID>`, `<PORT>`, `<PATH>`, `<실험경로>`는 실제 값으로 바꾸는 자리 표시자이며 그대로 실행하지 않는다. 아직 없는 API나 설정은 해당 단계에서 함께 만든다.

| 명령·도구 | 목적과 입력 | 처음 읽을 항목·종료 |
| --- | --- | --- |
| `kubectl get` / `describe` / `logs` | 실제 context·namespace 확인 후 실험 리소스를 읽는다. | Pod 상태·events·재시작·종료 이유·앱 로그. 명령별 옵션은 첫 사용 전에 설명. |
| `kubectl logs ... --previous` | 컨테이너 재시작 후 이전 인스턴스 로그를 확인한다. | 현재 로그와 이전 로그의 시간·인스턴스를 구분. 사용 가능 여부 확인. |
| 앱·cgroup·DB 관측 | 이전 Lab에서 사용한 증거를 Pod 실험과 연결한다. | 노드·Pod·컨테이너·JVM·DB의 관측 범위와 같은 시각. |

## 세부 커리큘럼

### KUBERNETES-01 — Pod와 자원 설정

- 배울 것: Pod·컨테이너·노드, CPU/memory requests·limits의 각 역할을 배운다.
- 안내 실습: 앱 하나부터 배포하고 CPU 제한·메모리 제한 실험을 각각 반복한다. 요청은 스케줄링, 제한은 자원 제어와 연결해 확인한다.
- 예상·가설 질문: Pending과 CPU throttling은 같은 단계의 문제일까?
- 완료 기준: events·cgroup·JVM 증거를 구분해 설명한다.

### KUBERNETES-02 — 준비 상태와 재시작

- 배울 것: readiness·liveness·startup, 트래픽 대상과 프로세스 수명 주기를 배운다.
- 안내 실습: 조건 하나씩 바꿔 요청 전달·probe 실패·재시작을 관찰한다. DB 지연과 앱 자체 실패를 분리한다.
- 예상·가설 질문: 일시적인 의존성 장애 때 앱 재시작은 어떤 영향을 줄까?
- 완료 기준: probe 설정·events·요청 결과의 관계와 재시작 전 로그를 기록한다.

### KUBERNETES-03 — 여러 Pod와 Worker 복구

- 배울 것: 서비스 라우팅, 다중 인스턴스, 메시지 재처리, metric 기반 확장을 배운다.
- 안내 실습: 외부 API/DB 지연·worker 종료·트래픽 증가 중 하나씩 재실험한다. HPA는 필요한 지표 경로를 구성한 뒤 선택 심화로 비교한다.
- 예상·가설 질문: Pod가 늘면 DB Pool 총 연결 수와 downstream 부하는 어떻게 될까?
- 완료 기준: 기존 장애 원인과 Kubernetes가 추가한 영향을 구분하고 사용자 결과·데이터 정합성을 재검증한다.

## 해석할 때 지킬 경계

requests를 전부 cgroup 제한과 동일시하지 않는다. 스케줄링, CPU 경합 시 배분, 실제 limit 적용을 나눠 배운다. 초기에는 단일 앱과 최소 리소스로 시작하고 전체 분산 서비스를 한 번에 배포하지 않는다.

## 수업과 기록

각 단계에서 기초 설명 → 정상 관찰 → 예상 → 조건 하나 변경 → 실제 관찰 → 가설과 검증 → 정리 순서로 진행한다. 도구 입문은 장애 주입이나 해결이 없어도 된다. 첫 실험은 안내형, 반복 실험은 힌트형, 마지막 적용은 독립형으로 도움을 줄인다.

실제 출력과 자기 설명은 [실험 기록 양식](../../../../../../../docs/EXPERIMENT-TEMPLATE.md)으로 남긴다. 현재 이 문서는 계획이며 어떤 단계도 완료로 표시하지 않는다. 다음 단계는 고정된 날짜가 아니라 실제 관찰과 이해를 확인한 뒤 선택한다.
