# Disk I/O / 용량과 저장 동작

디스크 공간과 읽기·쓰기 지연을 구분하고 Java 파일 쓰기를 OS 관측과 연결한다.

전체 위치와 순서: [CURRICULUM.md](../../../../../../../docs/CURRICULUM.md) · [현재 진도](../../../../../../../docs/PROGRESS.md)

## 시작 조건

CPU·Memory·Thread·Scheduler 입문. 별도의 실험 디렉터리와 파일 크기 상한을 먼저 정한다.

## 첫 설명

저장 공간이 얼마나 남았는지와 저장 장치가 얼마나 바쁜지는 다른 문제다. 파일 쓰기도 프로그램의 버퍼, OS의 page cache, 저장 장치까지 여러 단계를 거칠 수 있다.

## 도구를 처음 사용할 때

아래 표는 명령어 사전이다. 첫 수업에서는 필요한 명령 하나와 출력 항목 2~3개만 소개한다. `<PID>`, `<PORT>`, `<PATH>`, `<실험경로>`는 실제 값으로 바꾸는 자리 표시자이며 그대로 실행하지 않는다. 아직 없는 API나 설정은 해당 단계에서 함께 만든다.

| 명령·도구 | 목적과 입력 | 처음 읽을 항목·종료 |
| --- | --- | --- |
| `df -h <실험경로>` | 그 경로가 속한 파일시스템의 공간을 읽기 편한 단위로 출력한다. | Filesystem·Avail·Use%를 본다. 경로는 실제 실험 폴더로 바꾼다. 출력 후 종료. |
| `du -sh <실험경로>` | 경로 아래의 디스크 사용량을 합산한다. `-s`는 합계, `-h`는 읽기 편한 단위다. | 크기와 대상 경로. `df`와 측정 범위가 다르다. 종료까지 시간이 걸릴 수 있으며 Ctrl+C로 중단 가능. |
| `iostat -xz 1 5` | sysstat 설치 여부를 확인한 뒤 장치별 확장 I/O 지표를 1초 간격으로 5회 본다. `-x`는 확장, `-z`는 비활성 장치 생략이다. | 장치·r/s·w/s부터 시작해 await·%util을 추가한다. 자동 종료 또는 Ctrl+C. |
| Java 파일 쓰기 / `FileChannel.force(...)` | 심화에서 Java 버퍼 flush와 저장 동기화 요청의 의미를 비교한다. | 사용한 API·옵션, 파일 크기, 작업 시간, 대상 파일시스템을 기록한다. |

## 세부 커리큘럼

### DISK-01 — 남은 공간과 폴더 크기

- 배울 것: 파일·디렉터리·파일시스템, 용량 단위, 측정 범위를 배운다.
- 안내 실습: `df`와 `du`로 실험 폴더를 관찰하고 작은 제한된 파일을 생성·삭제하며 변화를 비교한다.
- 예상·가설 질문: 폴더 사용량과 파일시스템 사용량은 왜 꼭 같지 않을까?
- 완료 기준: 두 명령이 답하는 질문을 구분하고 실험 파일만 정리한다.

### DISK-02 — 파일 쓰기는 언제 느려질까

- 배울 것: I/O 요청, 처리량, 지연, 저장 장치 큐의 기초를 배운다.
- 안내 실습: 동일한 크기의 Java 파일 쓰기를 제한된 횟수로 수행하며 앱 시간과 iostat를 함께 본다. 첫 보고서와 이후 구간을 구분한다.
- 예상·가설 질문: 앱이 느린데 장치 통계가 낮다면 어떤 관측 범위나 캐시를 확인할까?
- 완료 기준: 작업 크기·시간·장치 지표를 함께 기록하고 용량 부족과 I/O 지연을 구분한다.

### DISK-03 — 버퍼·Page Cache·동기화

- 배울 것: 사용자 공간 버퍼, page cache, flush·fsync 개념과 저장 보장 범위를 배운다.
- 안내 실습: 작은 실험에서 버퍼 쓰기와 동기화 요청을 비교한다. 저장장치·파일시스템 차이를 기록하고 실제 전원 장애 실험은 하지 않는다.
- 예상·가설 질문: 쓰기 API 반환, 버퍼 flush, 저장 동기화 요청 완료는 각각 무엇을 뜻할까?
- 완료 기준: 측정 결과로 말할 수 있는 성능 차이와 확인하지 않은 내구성 보장을 구분한다.

## 해석할 때 지킬 경계

호스트 디스크를 꽉 채우지 않는다. 공간 고갈은 나중에 별도 크기 제한 볼륨에서만 다룬다. page cache를 전역으로 비우는 작업은 기본 실습에 포함하지 않는다. SSD·가상 디스크에서 %util 하나만으로 최대 성능 도달을 판정하지 않는다.

## 수업과 기록

각 단계에서 기초 설명 → 정상 관찰 → 예상 → 조건 하나 변경 → 실제 관찰 → 가설과 검증 → 정리 순서로 진행한다. 도구 입문은 장애 주입이나 해결이 없어도 된다. 첫 실험은 안내형, 반복 실험은 힌트형, 마지막 적용은 독립형으로 도움을 줄인다.

실제 출력과 자기 설명은 [실험 기록 양식](../../../../../../../docs/EXPERIMENT-TEMPLATE.md)으로 남긴다. 현재 이 문서는 계획이며 어떤 단계도 완료로 표시하지 않는다. 다음 단계는 고정된 날짜가 아니라 실제 관찰과 이해를 확인한 뒤 선택한다.
