# Memory / OS와 JVM 메모리

서버 전체 메모리, Java 프로세스 메모리, JVM Heap을 서로 다른 관측 범위로 읽는다.

전체 위치와 순서: [CURRICULUM.md](../../../../../../../docs/CURRICULUM.md) · [현재 진도](../../../../../../../docs/PROGRESS.md)

## 시작 조건

CPU-01~03. MEMORY-01~02는 F02, MEMORY-03~04는 H02에서 진행한다.

## 첫 설명

메모리는 실행 중인 코드와 데이터를 두는 공간이다. 서버 전체의 공간, Java 프로세스가 사용하는 공간, 그 안에서 객체를 두는 Heap은 같은 숫자가 아니다.

## 도구를 처음 사용할 때

아래 표는 명령어 사전이다. 첫 수업에서는 필요한 명령 하나와 출력 항목 2~3개만 소개한다. `<PID>`, `<PORT>`, `<PATH>`, `<실험경로>`는 실제 값으로 바꾸는 자리 표시자이며 그대로 실행하지 않는다. 아직 없는 API나 설정은 해당 단계에서 함께 만든다.

| 명령·도구 | 목적과 입력 | 처음 읽을 항목·종료 |
| --- | --- | --- |
| `free -h` | Linux 전체 메모리를 읽기 편한 단위로 한 번 출력한다. | 처음에는 total·available·buff/cache. `free`와 `available`을 구분한다. 출력 후 종료. |
| `top -p <PID>` | 앱 프로세스의 메모리를 반복 관찰한다. | RES·VIRT·%MEM의 의미와 표시 단위를 순서대로 배운다. `q`로 종료. |
| `jcmd <PID> GC.heap_info` | JVM Heap 관련 정보를 출력한다. 먼저 `jcmd <PID> help`로 지원 명령을 확인한다. | Heap의 사용·확보 정보와 GC 종류에 따른 출력 차이. 출력 후 종료; 강제 GC 명령은 아니다. |
| `jcmd <PID> VM.native_memory summary` | 선택 심화: NMT가 켜진 JVM에서 Native Memory Tracking 요약을 본다. | 시작 시 NMT 설정이 필요하다. committed/reserved와 RSS를 같은 값으로 취급하지 않는다. |

## 세부 커리큘럼

### MEMORY-01 — 서버 전체 메모리

- 배울 것: RAM, 사용 중인 공간, 사용 가능한 공간, page cache의 기초를 배운다.
- 안내 실습: `free -h`의 헤더와 단위를 읽고 정상 상태를 기록한다. 캐시가 있다는 이유만으로 메모리 부족으로 판단하지 않는다.
- 예상·가설 질문: 빈 공간이 적다는 것과 새 작업에 쓸 공간이 적다는 것은 같을까?
- 완료 기준: total·free·available을 자기 말로 구분한다.

### MEMORY-02 — Java 메모리는 Heap만이 아니다

- 배울 것: 가상 주소 공간·RSS·Heap·스레드 스택·Metaspace·Native 영역을 개략적으로 배운다.
- 안내 실습: 같은 시간대에 `top`과 Heap 정보를 읽는다. 영역을 모두 암기하기보다 어떤 범위를 측정하는지 표시한다.
- 예상·가설 질문: 프로세스 RES와 Heap used가 다르면 어느 도구가 틀린 걸까?
- 완료 기준: OS 전체 → 프로세스 → Heap의 범위를 그림이나 문장으로 설명한다.

### MEMORY-03 — 할당과 계속 보관하기

- 배울 것: 객체 할당, 참조, 도달 가능성, 회수 가능한 객체와 남아 있는 객체를 배운다.
- 안내 실습: 작은 양과 명확한 상한으로 객체를 일시 생성하는 경우와 컬렉션에 계속 보관하는 경우를 비교한다. 정리 API나 프로세스 종료 방법을 먼저 마련한다.
- 예상·가설 질문: 한 번 많이 할당한 것만으로 누수라고 말할 수 있을까? 중단 후 무엇을 더 봐야 할까?
- 완료 기준: 동일 조건에서 Heap 변화 추이를 기록하고 추가 관찰이 필요한 가설을 적는다.

### MEMORY-04 — 보관 경로 찾아보기

- 배울 것: GC 이후에도 객체가 남는 이유와 수명 관리 문제를 배운다.
- 안내 실습: GC 과정을 배운 뒤 저장 컬렉션의 보관·해제 동작을 바꾸고 동일 부하로 비교한다. 필요할 때만 histogram·heap dump를 도입한다.
- 예상·가설 질문: Heap이 줄어도 RSS가 바로 같은 폭으로 줄어야 할까?
- 완료 기준: 객체 보관 경로와 변경 효과를 근거로 설명한다. OOM은 GC-04에서 따로 실험한다.

## 해석할 때 지킬 경계

메모리 증가는 누수의 충분한 증거가 아니다. 실제 압박은 available, swap, Heap/GC 변화와 실험 조건을 함께 본다. page cache 제거, 무제한 할당, 호스트 메모리 고갈은 입문 과제로 사용하지 않는다.

## 수업과 기록

각 단계에서 기초 설명 → 정상 관찰 → 예상 → 조건 하나 변경 → 실제 관찰 → 가설과 검증 → 정리 순서로 진행한다. 도구 입문은 장애 주입이나 해결이 없어도 된다. 첫 실험은 안내형, 반복 실험은 힌트형, 마지막 적용은 독립형으로 도움을 줄인다.

실제 출력과 자기 설명은 [실험 기록 양식](../../../../../../../docs/EXPERIMENT-TEMPLATE.md)으로 남긴다. 현재 이 문서는 계획이며 어떤 단계도 완료로 표시하지 않는다. 다음 단계는 고정된 날짜가 아니라 실제 관찰과 이해를 확인한 뒤 선택한다.
