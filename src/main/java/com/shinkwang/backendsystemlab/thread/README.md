# Thread / 스레드 상태와 덤프

Java의 실행과 대기를 스레드 덤프에서 읽고 스택을 코드와 연결한다.

전체 위치와 순서: [CURRICULUM.md](../../../../../../../docs/CURRICULUM.md) · [현재 진도](../../../../../../../docs/PROGRESS.md)

## 시작 조건

CPU·Memory 입문. THREAD-01~03을 F03에서 마친 뒤 CPU-04로 돌아갈 수 있다.

## 첫 설명

스레드는 프로그램 안에서 일을 진행하는 흐름이다. 계산하고 있을 때도 있고, 시간이 지나거나 다른 작업이 끝나기를 기다릴 때도 있다. 덤프는 그 순간의 여러 흐름을 찍은 기록이다.

## 도구를 처음 사용할 때

아래 표는 명령어 사전이다. 첫 수업에서는 필요한 명령 하나와 출력 항목 2~3개만 소개한다. `<PID>`, `<PORT>`, `<PATH>`, `<실험경로>`는 실제 값으로 바꾸는 자리 표시자이며 그대로 실행하지 않는다. 아직 없는 API나 설정은 해당 단계에서 함께 만든다.

| 명령·도구 | 목적과 입력 | 처음 읽을 항목·종료 |
| --- | --- | --- |
| `ps -L -p <PID> -o pid,tid,stat,comm` | Linux에서 대상 프로세스의 스레드 목록을 출력한다. `-L`은 스레드, `-p`는 대상 PID, `-o`는 열 선택이다. | PID·TID와 OS 상태를 본다. OS 상태와 Java 상태를 동일시하지 않는다. 출력 후 종료. |
| `jcmd <PID> Thread.print` | Java 스레드 덤프를 출력한다. | 처음에는 이름·java.lang.Thread.State·스택 상단. 이후 lock 정보와 반복 덤프를 읽는다. 출력 후 종료. |
| `jstack <PID>` | 대안으로 JVM 스레드 덤프를 얻는다. | 같은 사용자·대상 JDK 환경을 확인한다. 두 도구를 처음부터 동시에 외울 필요는 없다. |

## 세부 커리큘럼

### THREAD-01 — 프로세스 하나에 여러 스레드

- 배울 것: 프로세스와 스레드의 관계, 공유 메모리와 각자의 실행 흐름을 배운다.
- 안내 실습: 정상 앱의 Linux 스레드 목록과 JVM 덤프를 보고 요청 처리·GC·기타 스레드의 이름을 찾아본다.
- 예상·가설 질문: 요청이 없는데도 왜 스레드가 여러 개일까?
- 완료 기준: 앱 전체 PID와 내부 TID를 구분하고 정상 덤프의 스레드 두 개를 설명한다.

### THREAD-02 — 시간을 기다리는 스레드

- 배울 것: Java의 NEW·RUNNABLE·BLOCKED·WAITING·TIMED_WAITING·TERMINATED를 순차적으로 소개한다.
- 안내 실습: 정상 관찰 후 짧은 sleep 작업을 추가하고 요청이 진행 중일 때 덤프를 본다. WAITING은 후속 신호를 기다리는 작은 예제로 비교한다.
- 예상·가설 질문: sleep 중인 요청과 계산 중인 요청은 같은 CPU를 사용할까?
- 완료 기준: 상태 이름만 외우지 않고 해당 스택과 코드의 대기 동작을 연결한다.

### THREAD-03 — 덤프 한 조각 읽기

- 배울 것: 호출 스택, 내 코드와 라이브러리 코드, 순간 관측의 한계를 배운다.
- 안내 실습: 튜터와 스레드 블록 하나를 줄 단위로 읽은 뒤 다른 블록을 혼자 설명한다. 같은 요청 구간에서 시차를 두고 덤프를 비교한다.
- 예상·가설 질문: 상태 하나만으로 원인을 확정할 수 있을까? 다음으로 어떤 코드나 지표를 볼까?
- 완료 기준: 이름 → 상태 → 스택 → 코드 → 추가 확인 항목을 설명한다. 이후 CPU-04에서 활용한다.

## 해석할 때 지킬 경계

Java RUNNABLE은 실제 CPU 사용을 보장하지 않는다. BLOCKED는 Java monitor 진입 대기를 뜻하며 모든 종류의 대기를 통칭하지 않는다. deadlock이나 락 경쟁은 concurrency에서 심화한다. 가상 스레드의 관찰 방식은 플랫폼 스레드 입문 뒤 다룬다.

## 수업과 기록

각 단계에서 기초 설명 → 정상 관찰 → 예상 → 조건 하나 변경 → 실제 관찰 → 가설과 검증 → 정리 순서로 진행한다. 도구 입문은 장애 주입이나 해결이 없어도 된다. 첫 실험은 안내형, 반복 실험은 힌트형, 마지막 적용은 독립형으로 도움을 줄인다.

실제 출력과 자기 설명은 [실험 기록 양식](../../../../../../../docs/EXPERIMENT-TEMPLATE.md)으로 남긴다. 현재 이 문서는 계획이며 어떤 단계도 완료로 표시하지 않는다. 다음 단계는 고정된 날짜가 아니라 실제 관찰과 이해를 확인한 뒤 선택한다.
