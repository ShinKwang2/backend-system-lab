# Container / cgroup과 자원 제한

앱을 제한된 자원 안에서 실행하고 JVM 오류와 cgroup의 프로세스 종료를 구분한다.

전체 위치와 순서: [CURRICULUM.md](../../../../../../../docs/CURRICULUM.md) · [현재 진도](../../../../../../../docs/PROGRESS.md)

## 시작 조건

CPU·Scheduler·Memory·GC·Heap OOM. 실제 컨테이너 런타임과 cgroup 버전을 확인한다.

## 첫 설명

컨테이너의 프로그램도 프로세스다. cgroup은 프로세스 집합의 자원 사용을 관리한다. 앱이 내부에서 실패하는 경우와 밖에서 자원 제한으로 종료되는 경우를 비교한다.

## 도구를 처음 사용할 때

아래 표는 명령어 사전이다. 첫 수업에서는 필요한 명령 하나와 출력 항목 2~3개만 소개한다. `<PID>`, `<PORT>`, `<PATH>`, `<실험경로>`는 실제 값으로 바꾸는 자리 표시자이며 그대로 실행하지 않는다. 아직 없는 API나 설정은 해당 단계에서 함께 만든다.

| 명령·도구 | 목적과 입력 | 처음 읽을 항목·종료 |
| --- | --- | --- |
| 컨테이너 inspect·stats·로그 | 사용하는 런타임의 명령을 도입 시 설명한다. | 실제 설정·PID·메모리·CPU·종료 코드·OOM 관련 상태. 호스트와 컨테이너 관측 범위 구분. |
| cgroup v2 파일 | 읽기 관찰부터 시작한다. v2라면 cpu.max·cpu.stat·memory.max·memory.current·memory.events를 확인한다. | quota·period·throttling, 현재 메모리·제한·OOM 이벤트. v1에는 그대로 적용하지 않는다. |
| JVM flags·Heap·GC 로그 | 실제 JVM이 인식한 자원과 내부 사용을 확인한다. | Heap 최대값·GC·오류 메시지. 메모리 limit 전체를 Heap으로 배정하지 않는다. |

## 세부 커리큘럼

### CONTAINER-01 — 같은 앱과 다른 자원 범위

- 배울 것: 프로세스 격리와 cgroup, 호스트/컨테이너의 관측 범위를 배운다.
- 안내 실습: 정상 앱의 버전·limit·JVM 설정을 기록하고 호스트 관측과 컨테이너 지표를 비교한다.
- 예상·가설 질문: 컨테이너 지표와 호스트 전체 숫자가 다르면 무엇을 확인할까?
- 완료 기준: 측정 대상과 적용된 자원 제한을 근거로 설명한다.

### CONTAINER-02 — CPU 제한과 Throttling

- 배울 것: quota·period·throttling과 실제 CPU 수의 차이를 배운다.
- 안내 실습: 동일 계산 부하에서 CPU 제한 하나만 바꾸고 처리량·지연·cpu.stat 변화를 비교한다.
- 예상·가설 질문: CPU가 더 필요할 때 제한에 걸린 증거는 어디서 볼까?
- 완료 기준: 제한·throttling·API 변화의 근거를 연결한다.

### CONTAINER-03 — Heap OOM과 cgroup OOM

- 배울 것: Heap 밖의 메모리, cgroup 메모리 한계, 프로세스 kill의 증거를 배운다.
- 안내 실습: 격리 컨테이너에서 JVM Heap OOM과 cgroup OOM을 따로 재현한다. 호스트 여유와 제한을 먼저 확인하고 로그·events·런타임 상태를 함께 기록한다.
- 예상·가설 질문: 종료 코드 137만으로 OOM을 확정할 수 있을까? JVM 오류 로그가 없으면 무엇을 더 볼까?
- 완료 기준: 실제 오류·OOM 이벤트·런타임 종료 원인으로 두 사례를 구분하고 재검증한다.

## 해석할 때 지킬 경계

JVM OutOfMemoryError의 발생과 프로세스 전체 종료는 같은 사실이 아니다. SIGKILL이나 exit 137만으로 OOM을 단정하지 않는다. 호스트 OOM을 목표로 하지 않으며 실제 cgroup 계층과 이벤트를 확인한다.

## 수업과 기록

각 단계에서 기초 설명 → 정상 관찰 → 예상 → 조건 하나 변경 → 실제 관찰 → 가설과 검증 → 정리 순서로 진행한다. 도구 입문은 장애 주입이나 해결이 없어도 된다. 첫 실험은 안내형, 반복 실험은 힌트형, 마지막 적용은 독립형으로 도움을 줄인다.

실제 출력과 자기 설명은 [실험 기록 양식](../../../../../../../docs/EXPERIMENT-TEMPLATE.md)으로 남긴다. 현재 이 문서는 계획이며 어떤 단계도 완료로 표시하지 않는다. 다음 단계는 고정된 날짜가 아니라 실제 관찰과 이해를 확인한 뒤 선택한다.
