# Database / 쿼리·트랜잭션·MVCC

DB 내부의 실행 계획과 대기를 읽고 Spring 요청의 지연·정합성과 연결한다.

전체 위치와 순서: [CURRICULUM.md](../../../../../../../docs/CURRICULUM.md) · [현재 진도](../../../../../../../docs/PROGRESS.md)

## 시작 조건

기초 6개와 JVM 심화. DATABASE-01 시작 시 실험용 PostgreSQL과 최소 JDBC 연결만 추가한다.

## 첫 설명

DB 요청은 연결을 통해 전달되고, DB가 데이터를 찾거나 변경한 뒤 결과를 반환한다. 데이터 양, 접근 방법, 동시 트랜잭션 때문에 작업 시간과 결과가 달라질 수 있다.

## 도구를 처음 사용할 때

아래 표는 명령어 사전이다. 첫 수업에서는 필요한 명령 하나와 출력 항목 2~3개만 소개한다. `<PID>`, `<PORT>`, `<PATH>`, `<실험경로>`는 실제 값으로 바꾸는 자리 표시자이며 그대로 실행하지 않는다. 아직 없는 API나 설정은 해당 단계에서 함께 만든다.

| 명령·도구 | 목적과 입력 | 처음 읽을 항목·종료 |
| --- | --- | --- |
| `psql` | 실험 DB에 접속해 SQL을 실행한다. 접속 인자는 실제 환경 기준으로 설명한다. | DB·사용자·SQL 결과·트랜잭션 상태. `\q`로 종료. 비밀 값은 기록하지 않는다. |
| `EXPLAIN` / `EXPLAIN (ANALYZE, BUFFERS)` | 계획과 실제 실행을 비교한다. ANALYZE는 쿼리를 실제 실행한다. | 처음에는 Scan 종류·rows·실행 시간, 이후 추정 오차·buffer. 입문은 SELECT에 사용한다. |
| `pg_stat_activity`, `pg_locks`, `pg_blocking_pids(...)` | 활동 중인 쿼리와 대기·차단 관계를 읽는다. | 튜터가 필요한 SELECT부터 설명한다. 대기 이벤트·세션·트랜잭션과 잠금 관계. |
| 두 SQL 세션 | 서로 다른 트랜잭션을 순서대로 진행한다. | BEGIN·COMMIT·ROLLBACK 시점과 실행 순서를 기록한다. |

## 세부 커리큘럼

### DATABASE-01 — DB 연결과 작은 데이터

- 배울 것: 테이블·행·키·SQL·트랜잭션의 기초를 확인한다. 이미 아는 부분은 짧게 점검한다.
- 안내 실습: 버전과 실험 DB를 기록하고 최소 조회 API와 같은 SELECT의 직접 실행을 비교한다. 데이터 초기화·정리 범위를 정한다.
- 예상·가설 질문: HTTP 요청 전체 시간과 SQL 실행 시간은 같은 값일까?
- 완료 기준: 요청 → 연결 → SQL → 결과의 경로와 측정 범위를 설명한다.

### DATABASE-02 — 인덱스 전후의 실행 계획

- 배울 것: sequential scan, B-tree index, 선택도, page·buffer를 필요한 순서로 배운다.
- 안내 실습: 제한된 재현 데이터에서 동일한 조건의 조회를 인덱스 전후로 비교한다. 캐시와 반환 행 수를 기록한다.
- 예상·가설 질문: 인덱스가 있어도 sequential scan을 선택할 수 있을까?
- 완료 기준: 계획·실행 시간·행 수를 근거로 설명하고 특정 Scan을 무조건 정답으로 취급하지 않는다.

### DATABASE-03 — 트랜잭션이 다른 요청을 기다리게 할 때

- 배울 것: row lock, 트랜잭션 범위, 차단과 deadlock을 배운다.
- 안내 실습: 두 세션으로 같은 행을 수정하며 lock holder와 waiter를 찾는다. 짧은 제한 시간과 rollback 정리를 준비한다.
- 예상·가설 질문: 대기 중인 쿼리만 보면 원인을 충분히 알 수 있을까?
- 완료 기준: 누가 무엇을 잡고 누가 기다리는지 설명하고 종료 후 잠금 해제를 확인한다.

### DATABASE-04 — 격리 수준과 MVCC

- 배울 것: snapshot, isolation, non-repeatable read·phantom·lost update를 차례로 배운다.
- 안내 실습: 동일한 두 세션 순서를 격리 수준별로 실행하고 실제 결과를 표로 비교한다. PostgreSQL 버전의 보장과 가능한 이상 현상을 먼저 확인한다.
- 예상·가설 질문: 격리 수준 이름과 실제 DB의 보장이 같을까? dirty read가 이 DB에서 재현 가능한가?
- 완료 기준: 실행 순서·설정·결과를 기록하고 일반 이론과 PostgreSQL 동작을 구분한다.

## 해석할 때 지킬 경계

EXPLAIN ANALYZE는 실제 작업을 수행하므로 변경 쿼리는 별도 통제 없이 실행하지 않는다. PostgreSQL에서 READ UNCOMMITTED는 READ COMMITTED처럼 동작한다. 모든 교과서의 이상 현상이 모든 DB·격리 수준에서 재현된다고 가정하지 않는다.

## 수업과 기록

각 단계에서 기초 설명 → 정상 관찰 → 예상 → 조건 하나 변경 → 실제 관찰 → 가설과 검증 → 정리 순서로 진행한다. 도구 입문은 장애 주입이나 해결이 없어도 된다. 첫 실험은 안내형, 반복 실험은 힌트형, 마지막 적용은 독립형으로 도움을 줄인다.

실제 출력과 자기 설명은 [실험 기록 양식](../../../../../../../docs/EXPERIMENT-TEMPLATE.md)으로 남긴다. 현재 이 문서는 계획이며 어떤 단계도 완료로 표시하지 않는다. 다음 단계는 고정된 날짜가 아니라 실제 관찰과 이해를 확인한 뒤 선택한다.
