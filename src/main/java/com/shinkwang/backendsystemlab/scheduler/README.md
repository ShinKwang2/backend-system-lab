# Load / Scheduler

CPU 사용률, 실행 대기, load average, context switch를 서로 다른 지표로 읽는다.

전체 위치와 순서: [CURRICULUM.md](../../../../../../../docs/CURRICULUM.md) · [현재 진도](../../../../../../../docs/PROGRESS.md)

## 시작 조건

CPU·Memory·Thread 입문. Disk 학습 후 I/O 대기 사례를 다시 비교한다.

## 첫 설명

CPU에서 일하려는 스레드가 동시에 많으면 순서를 나눠 실행해야 한다. 스케줄러는 실행할 작업을 고른다. 얼마나 바쁜지와 얼마나 기다리는지는 다른 질문이다.

## 도구를 처음 사용할 때

아래 표는 명령어 사전이다. 첫 수업에서는 필요한 명령 하나와 출력 항목 2~3개만 소개한다. `<PID>`, `<PORT>`, `<PATH>`, `<실험경로>`는 실제 값으로 바꾸는 자리 표시자이며 그대로 실행하지 않는다. 아직 없는 API나 설정은 해당 단계에서 함께 만든다.

| 명령·도구 | 목적과 입력 | 처음 읽을 항목·종료 |
| --- | --- | --- |
| `vmstat 1 5` | 1초 간격으로 5개 보고서를 출력한다. 숫자 1은 간격, 5는 횟수다. | 처음에는 r·us·id, 이후 b·cs·sy·wa. 정해진 횟수 뒤 종료하며 중간에 Ctrl+C로 중단 가능. |
| `top` | 서버 전체 CPU와 load average를 반복 관찰한다. | load의 1·5·15분 값과 CPU 수를 구분한다. `q`로 종료. |
| `nproc` | 현재 프로세스에서 사용할 수 있는 처리 장치 수를 확인하는 출발점이다. | 출력 후 종료. 컨테이너 자원 제약은 뒤 과정에서 추가 확인한다. |

## 세부 커리큘럼

### SCHEDULER-01 — 실행 순서를 기다리기

- 배울 것: vCPU, runnable, 실행 대기, 스케줄러를 쉬운 작업 대기열로 설명한다.
- 안내 실습: 정상 상태에서 `vmstat` 헤더를 읽고 그 뒤 보고서를 비교한다. 첫 보고서의 CPU·rate 값과 이후 구간 값을 구분한다.
- 예상·가설 질문: r 값이 잠깐 커졌다는 것과 계속 큰 것은 같은 의미일까?
- 완료 기준: 각 열의 단위와 관측 구간을 적고 r·CPU 사용률을 함께 읽는다.

### SCHEDULER-02 — 일하는 흐름 수를 늘리기

- 배울 것: 동시성, 처리량, 응답 시간, context switch를 배운다.
- 안내 실습: 동일한 계산 작업으로 동시성을 조금씩 늘리며 `vmstat`와 응답 시간을 기록한다. 시간·요청 상한을 유지한다.
- 예상·가설 질문: 스레드를 두 배로 만들면 처리량도 두 배가 될까? cs가 증가했다는 사실만으로 병목을 확정할 수 있을까?
- 완료 기준: 동시성별 관측표와 이를 설명하는 가설을 남긴다.

### SCHEDULER-03 — Load와 CPU는 같은 값일까

- 배울 것: Linux load average의 실행 가능 작업과 uninterruptible 대기를 소개한다.
- 안내 실습: 계산 실험과 Disk 학습 후의 I/O 대기 사례를 비교한다. 입문에서는 높은 I/O 대기를 억지로 만들 필요는 없다.
- 예상·가설 질문: CPU가 낮은데 load가 높다면 어떤 추가 관찰이 필요할까?
- 완료 기준: load를 CPU 사용률의 다른 이름으로 설명하지 않고 확인할 지표 두 개를 고른다.

## 해석할 때 지킬 경계

`vmstat`의 첫 보고서는 CPU·rate 항목에서 부팅 이후 평균을 포함한다. 이후 간격 보고서와 무심코 섞지 않는다. r·b 같은 순간 값과 cs 같은 초당 값도 구분한다. 높은 load나 cs 한 가지로 원인을 단정하지 않는다.

## 수업과 기록

각 단계에서 기초 설명 → 정상 관찰 → 예상 → 조건 하나 변경 → 실제 관찰 → 가설과 검증 → 정리 순서로 진행한다. 도구 입문은 장애 주입이나 해결이 없어도 된다. 첫 실험은 안내형, 반복 실험은 힌트형, 마지막 적용은 독립형으로 도움을 줄인다.

실제 출력과 자기 설명은 [실험 기록 양식](../../../../../../../docs/EXPERIMENT-TEMPLATE.md)으로 남긴다. 현재 이 문서는 계획이며 어떤 단계도 완료로 표시하지 않는다. 다음 단계는 고정된 날짜가 아니라 실제 관찰과 이해를 확인한 뒤 선택한다.
