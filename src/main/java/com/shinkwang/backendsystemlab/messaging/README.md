# Messaging / 중복 처리와 Outbox

처리와 확인 사이의 실패, DB와 메시지 발행 사이의 실패를 재현해 보장 범위를 설명한다.

전체 위치와 순서: [CURRICULUM.md](../../../../../../../docs/CURRICULUM.md) · [현재 진도](../../../../../../../docs/PROGRESS.md)

## 시작 조건

DB 트랜잭션·정합성·다중 인스턴스 기초. 필요해지는 시점에 Kafka와 작은 worker를 추가한다.

## 첫 설명

메시지 전달과 업무 처리는 각각 성공하거나 실패할 수 있다. 처리 성공을 알리는 단계 전에 worker가 종료되면 같은 일을 다시 받는 상황을 실험한다.

## 도구를 처음 사용할 때

아래 표는 명령어 사전이다. 첫 수업에서는 필요한 명령 하나와 출력 항목 2~3개만 소개한다. `<PID>`, `<PORT>`, `<PATH>`, `<실험경로>`는 실제 값으로 바꾸는 자리 표시자이며 그대로 실행하지 않는다. 아직 없는 API나 설정은 해당 단계에서 함께 만든다.

| 명령·도구 | 목적과 입력 | 처음 읽을 항목·종료 |
| --- | --- | --- |
| 브로커·consumer 설정과 로그 | 사용하는 제품·버전의 확인/offset commit 시점을 먼저 확인한다. | 메시지 ID·partition·offset·수신·처리·commit 시각. Kafka에서는 offset commit 용어를 사용. |
| DB 조회 | 동일 메시지의 처리 결과와 중복 방지 키를 확인한다. | 메시지 전달 횟수와 업무 반영 횟수를 구분. |
| worker 종료와 재시작 | 별도 worker의 지정된 실패 지점에서 프로세스를 종료한다. | 진행 중인 상태·재시작 후 전달과 처리. 종료 대상과 복구 절차를 먼저 확인. |

## 세부 커리큘럼

### MESSAGING-01 — 처리 성공 후 확인 전에 종료

- 배울 것: at-most-once·at-least-once와 처리/commit 간격을 배운다.
- 안내 실습: 업무 DB 반영 후 offset commit 전의 실패를 통제해 재현한다. 재시작 후 전달·처리 횟수를 기록한다.
- 예상·가설 질문: 전달이 한 번이라는 보장과 DB 업무 반영이 한 번이라는 보장은 같을까?
- 완료 기준: 실패 지점과 재처리 흐름을 타임라인으로 설명한다.

### MESSAGING-02 — 멱등성과 중복 제거

- 배울 것: 업무 식별자, unique constraint, 중복 처리 기록과 결과 반영의 원자성을 배운다.
- 안내 실습: 같은 ID 반복 전달과 동시 중복 처리를 비교한다. 중복 방지 기록과 업무 변경을 같은 트랜잭션에서 처리하는 방법을 검증한다.
- 예상·가설 질문: 중복 방지 기록만 저장하고 업무 반영 전에 죽으면 어떻게 될까?
- 완료 기준: 성공·실패·재시작 경우에서 업무 결과가 유지되는지 확인하고 보장 범위를 적는다.

### MESSAGING-03 — Dual Write와 Outbox

- 배울 것: 두 시스템 쓰기의 실패 구간, outbox transaction, 재발행·eventual consistency를 배운다.
- 안내 실습: DB 저장 후 발행 전 실패를 재현하고 outbox 행과 업무 변경을 함께 저장한다. 전달 worker의 재시도·중복도 검증한다. CDC는 선택 심화다.
- 예상·가설 질문: Outbox가 메시지의 중복 전달까지 없애줄까?
- 완료 기준: 업무·outbox·발행·consumer의 실패 지점과 누락/중복 대응을 설명한다.

## 해석할 때 지킬 경계

Kafka의 exactly-once 기능이 외부 DB까지 모든 업무를 자동으로 한 번만 처리한다는 뜻은 아니다. 제품과 트랜잭션 범위를 먼저 확인한다. ACK라는 일반 설명을 실제 Kafka offset commit과 무심코 혼용하지 않는다.

## 수업과 기록

각 단계에서 기초 설명 → 정상 관찰 → 예상 → 조건 하나 변경 → 실제 관찰 → 가설과 검증 → 정리 순서로 진행한다. 도구 입문은 장애 주입이나 해결이 없어도 된다. 첫 실험은 안내형, 반복 실험은 힌트형, 마지막 적용은 독립형으로 도움을 줄인다.

실제 출력과 자기 설명은 [실험 기록 양식](../../../../../../../docs/EXPERIMENT-TEMPLATE.md)으로 남긴다. 현재 이 문서는 계획이며 어떤 단계도 완료로 표시하지 않는다. 다음 단계는 고정된 날짜가 아니라 실제 관찰과 이해를 확인한 뒤 선택한다.
