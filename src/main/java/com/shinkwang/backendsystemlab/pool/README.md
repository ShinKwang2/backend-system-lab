# HikariCP / 커넥션 풀

DB 연결을 얻기 위한 대기와 SQL 실행 중 대기를 구분한다.

전체 위치와 순서: [CURRICULUM.md](../../../../../../../docs/CURRICULUM.md) · [현재 진도](../../../../../../../docs/PROGRESS.md)

## 시작 조건

DATABASE-01~03, Thread 덤프, 외부 의존성 지연 관찰. 필요한 Actuator 지표는 이 단계에서 사용한다.

## 첫 설명

커넥션 풀은 사용할 DB 연결을 제한된 수만큼 관리한다. 연결을 빌린 요청은 반환할 때까지 그 연결을 사용하며, 다른 요청은 사용 가능한 연결을 기다릴 수 있다.

## 도구를 처음 사용할 때

아래 표는 명령어 사전이다. 첫 수업에서는 필요한 명령 하나와 출력 항목 2~3개만 소개한다. `<PID>`, `<PORT>`, `<PATH>`, `<실험경로>`는 실제 값으로 바꾸는 자리 표시자이며 그대로 실행하지 않는다. 아직 없는 API나 설정은 해당 단계에서 함께 만든다.

| 명령·도구 | 목적과 입력 | 처음 읽을 항목·종료 |
| --- | --- | --- |
| Hikari 설정과 지표 | 실험 버전의 maximumPoolSize·connectionTimeout과 실제 풀 이름을 확인한다. | active·idle·pending·max 등 사용 가능한 지표. 지표 이름·단위는 실제 Actuator 목록에서 확인. |
| `jcmd <PID> Thread.print` | 풀 획득 대기와 DB 호출 스택을 비교한다. | 상태뿐 아니라 호출 경로를 읽는다. 출력 후 종료. |
| DB 활동·잠금 조회 | connection holder가 어떤 작업을 하는지 조사한다. | 쿼리·트랜잭션·대기 관계. HTTP·JVM·DB의 관측 시각을 맞춘다. |

## 세부 커리큘럼

### POOL-01 — 빌리고 반환하기

- 배울 것: 연결 생성·재사용·반환, 풀 크기, acquire wait를 배운다.
- 안내 실습: 정상 요청의 지표와 덤프를 읽고 요청 동시성이 낮을 때 기준을 기록한다.
- 예상·가설 질문: active는 쿼리를 CPU에서 실행 중이라는 뜻일까?
- 완료 기준: 요청 스레드와 DB 연결이 다른 자원임을 설명한다.

### POOL-02 — 작은 풀에서 기다리기

- 배울 것: 풀 고갈, 대기 요청, 커넥션 획득 timeout을 배운다.
- 안내 실습: 실험 프로필에서 풀을 2개로 줄이고 연결 보유 시간을 통제한 뒤 작은 동시성부터 증가시킨다. active·pending·덤프·DB 상태를 함께 본다.
- 예상·가설 질문: active=max만으로 장애일까? 반환이 늦는 이유는 어디서 확인할까?
- 완료 기준: 풀 획득 대기와 연결 보유 원인을 구분하는 근거를 남긴다.

### POOL-03 — 원인별 해결 비교

- 배울 것: 느린 SQL·락·긴 트랜잭션·반환 누락의 차이와 풀 확대의 비용을 배운다.
- 안내 실습: 확인된 연결 보유 원인을 먼저 개선하고 동일 부하로 재검증한다. 풀 크기·timeout 변경은 한 조건씩 비교한다.
- 예상·가설 질문: 풀을 늘리면 DB에서 어떤 부담이 생길까? timeout은 원인을 없앨까?
- 완료 기준: 변경 효과·DB 영향·실패 응답을 비교하고 해결과 완화를 구분한다.

## 해석할 때 지킬 경계

작은 풀이나 active=max 자체가 항상 문제는 아니다. 대기 시간·실패·처리량과 연결 보유 원인을 함께 본다. Hikari connectionTimeout은 커넥션 획득 제한이며 SQL 실행 timeout과 다르다.

## 수업과 기록

각 단계에서 기초 설명 → 정상 관찰 → 예상 → 조건 하나 변경 → 실제 관찰 → 가설과 검증 → 정리 순서로 진행한다. 도구 입문은 장애 주입이나 해결이 없어도 된다. 첫 실험은 안내형, 반복 실험은 힌트형, 마지막 적용은 독립형으로 도움을 줄인다.

실제 출력과 자기 설명은 [실험 기록 양식](../../../../../../../docs/EXPERIMENT-TEMPLATE.md)으로 남긴다. 현재 이 문서는 계획이며 어떤 단계도 완료로 표시하지 않는다. 다음 단계는 고정된 날짜가 아니라 실제 관찰과 이해를 확인한 뒤 선택한다.
