# CPU-01 — Spring Boot를 Linux 프로세스로 찾기

상태: 완료 · 관찰일: 2026-10-15(KST) · 환경: E01

## 목표와 확인 결과

Spring 시작 로그의 PID를 OS 출력과 대조하고, 실행 인자로 Java 프로그램을 구분했다. 재시작 후 PID 변화와 부모 종료 후 재부모화도 관찰했다.

이 문서의 PID는 당시 관찰값이다. 재현할 때는 새 시작 로그와 `jps -l`에서 찾은 번호로 바꾼다. `<APP_PID>`, `<PARENT_PID>`는 자리 표시자이며 꺾쇠까지 실제 숫자로 치환한다.

## 실행 위치와 터미널

- Mac: 코드·문서 편집과 Git 작업.
- Linux A: `/home/skl/backend-system-lab`에서 앱 실행. 실행 중에는 이 터미널을 유지.
- Linux B: 같은 VM의 관찰용 터미널. `ps`, `jps`는 프로젝트 밖에서도 실행 가능.
- 관측 근거: 사용자 제공 출력·로그와 사용자 설명. AI가 VM에서 대신 측정하지 않았다.

## 앱 관찰 — 실행 순서와 명령

| 순서 | 터미널 | 명령·조작 | 목적과 실제 결과 |
| --- | --- | --- | --- |
| 1 | A, 프로젝트 루트 | `./gradlew bootRun` | 기본 앱 기동. 로그 PID 46883, HTTP 8080 |

| 9 | B | `jps -l` | 앱·Wrapper가 목록에서 사라지고 데몬 46752는 남음 |
| 10 | A, 프로젝트 루트 | `./gradlew bootRun` | 재실행 |
| 11 | B | `jps -l` | 앱 47487, Wrapper 47427, 데몬 46752 |
| 12 | B | `ps -p 46752 -o pid,ppid,comm` | 데몬의 PPID가 1로 바뀜 |
| 13 | B | `ps -p 1 -o pid,ppid,comm` | PID 1, PPID 0, systemd |

재현용 조회 형식:

```bash
ps -p <APP_PID> -o pid,ppid,comm,args
ps -ww -p <PARENT_PID> -o pid,ppid,comm,args
jps -l
```

## 명령 읽는 법

- `ps`: 프로세스 정보 조회. `-p`는 PID 선택, `-o`는 열 선택, `-ww`는 긴 출력의 폭 제한 해제.
- `PID`: 해당 프로세스 번호. `PPID`: 현재 부모 프로세스 번호.
- `comm`: 명령 이름. `args`: 실행 명령과 인자. 둘 다 헤더에 COMMAND로 표시될 수 있음.
- `jps`: 접근 가능한 Java 프로세스의 짧은 이름. `-l`은 전체 메인 클래스/JAR 경로. 일반적인 이번 실행에서 앞 번호를 ps의 PID와 대조함.
- `command -v`: 현재 셸이 명령을 찾는 위치 확인. 파일 경로와 실행 중인 프로세스는 구분.
- 조회 명령은 출력 후 종료. `bootRun`은 서버를 유지하며 A의 Ctrl+C로 중단.

## 예상·학습자의 설명·수정한 이해

- 최초 생각: comm이 java인 것과 PID 숫자만으로는 앱을 찾기 어렵다. args의 메인 클래스로 찾을 수 있을 것 같다.
- 확인: 메인 클래스가 실제 args에 있었다. 시작 로그에서 얻은 PID도 OS 조회와 연결할 수 있다. PID 숫자 자체에 프로그램 역할이 담기지는 않는다.
- 긴 명령을 눈으로 읽기 어렵다는 질문에서 jps -l 요약 도구를 배웠다. 메인 클래스 뒤에 앱 인자가 올 수도 있어 마지막 단어만 고정적으로 보지 않는다.
- 재시작 전 예상: PID가 달라질 것 같다. 누가 번호를 정하는지는 모르겠다.
- 보완: Linux 커널이 PID를 부여하며 종료된 번호는 재사용될 수 있다. 이번 앱의 PID는 실제로 달라졌다.
- 부모가 사라지면 자식도 반드시 종료되는 것은 아니다. 데몬 46752는 systemd 1의 자식으로 재부모화됐다.
- 새 Wrapper가 기존 데몬에 일을 요청하는 통신 관계와 OS의 부모 관계는 별개다. 소켓 통신 자체는 이번에 관찰하지 않았다.
- jps도 실행 동안 자신의 JVM을 목록에 보여줬다. 설치된 파일과 실행 중인 프로세스는 다르다.
