### 첫 기초 설명

- 시간·이벤트 대기: Thread.sleep처럼 시간이 지나거나 조건이 갖춰져야 다음 일을 할 수 있는 경우다.
- CPU 실행 차례 대기: 계산할 준비는 되었지만 다른 스레드가 CPU에서 실행 중이라 차례를 기다리는 경우다.
- 스케줄러: 실행 가능한 작업들 가운데 CPU에서 실행할 것을 고르는 Linux 커널의 기능이다.
- 설명용 예시: 논리 CPU 1개에서 계산할 준비가 된 스레드 3개가 있다면 한 순간에는 하나가 실행하고 다른 둘은 실행 차례를 기다릴 수 있다. 실제 측정값이 아니다.
- nproc 4 재확인 후 vmstat를 안내한다. vmstat는 서버 전체의 메모리·CPU·실행 가능한 작업 등을 보여주는 도구다. 이번에는 r(실행 중이거나 CPU 실행 차례를 기다리는 작업 수, 개수), us(사용자 영역 CPU 시간 비율, %), id(CPU 유휴 시간 비율, %)만 읽는다. r에는 실행 중인 작업도 포함되므로 순수 대기 수로 해석하지 않는다.
- CPU 비율은 전체 CPU 시간 기준이다. 첫 번째 자료 행의 CPU 값은 부팅 이후 평균을 포함하고 두 번째 자료 행부터는 직전 1초 구간의 값이다. r은 각 관측 시점의 값으로 구분한다. 근거: [procps-ng vmstat 매뉴얼](https://man7.org/linux/man-pages/man8/vmstat.8.html).
- 읽기 예시(실측 아님): r=2, us=3, id=96이면 관측 순간 실행 가능한 작업이 2개이며 해당 CPU 관측 구간에서 사용자 영역 3%, 유휴 96%라는 뜻이다. 나머지 CPU 항목은 이번에는 읽지 않는다.
